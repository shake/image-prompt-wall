# Codex 部署检查清单

这份清单适合每次让 Codex 改完 Image Prompt Wall 之后，用来做最终确认。

目标很简单：**改动要小、验证要全、上线要稳。**

## 1. 先看改动范围

- 这次改的是页面文案，还是交互逻辑
- 是否涉及 `src/index.ts`
- 是否改了 `wrangler.jsonc`
- 是否改了 `migrations/`
- 是否需要同步 README 或部署指南

如果只是文案，尽量不要顺手改结构。

## 2. 先确认边界

- 是否仍然保持「首页 / 详情页 / `/admin`」三段式结构
- 是否仍然保持前台公开、后台受 Access 保护
- 是否仍然保持 D1 管元数据、R2 管图片
- 是否仍然保持最多 2 张图片
- 是否仍然保持删除和恢复逻辑不变

如果边界变了，要先说明，再改代码。

## 3. 再检查本地

在本地至少做一次：

```bash
npm install
npm run check
```

如果这次改动会影响数据库，再补跑：

```bash
npm run d1:migrate
```

## 4. 再看页面

至少确认这些页面：

- 首页
- 任意详情页
- `/admin`
- `/admin/entry/:id`

重点看这些交互有没有坏：

- 图片是否能正常切换
- 复制按钮是否还在
- 编辑按钮是否还在
- 删除确认是否还在
- 上传按钮是否还在
- 主题和中英文切换是否还在

## 5. 再确认 Cloudflare

如果这次改动涉及上线，需要再确认：

- Worker 是否已经部署成功
- D1 迁移是否已经生效
- R2 绑定是否正常
- Custom Domain 是否仍然指向正确 Worker
- Access 是否仍然只放行正确邮箱

## 6. 最后确认发布记录

每次改完，建议固定记录这四项：

- Git 提交
- Cloudflare 版本
- 访问链接
- 是否包含数据库迁移

如果这次没有部署，也要明确说“仅本地修改，未发布”。

## 7. 推荐的收尾标准

只有满足下面几条，才算这次改动真的完成：

- 代码检查通过
- 页面功能正常
- Cloudflare 配置没有断
- README 或部署文档没有和实际行为打架
- 你能在 30 秒内说清楚这次改了什么

## 8. 给 Codex 的固定指令

以后你如果继续让 Codex 改这个项目，可以直接按这个顺序说：

1. 先说这次要改什么
2. 说明哪些边界不能动
3. 改完先检查本地
4. 再检查 Cloudflare
5. 最后回报 Git 提交、Cloudflare 版本和访问链接
